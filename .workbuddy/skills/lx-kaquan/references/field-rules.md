# 卡券字段规则

依据用户提供的两份宏鹄模板“重要说明”和当前已确认业务要求。模板文件保留在 `assets/`；用户输入覆盖默认，但不绕过字段约束。

## 两类模板差异

| 类型 | 列数 | 固定规则枚举 | 独有字段 |
| --- | --- | --- | --- |
| 免佣卡 `mianyong` | 27 | 单单免佣、每天前x单免佣、累计前x单免佣 | 无 |
| 飞涨卡 `feizhang` | 29 | 单单飞涨、每天前x单飞涨、累计前x单飞涨 | reward_percent、max_amount_of_order |

“活动信息”第 1/2 行不能重排或改名。免佣卡第 I/J 列是 stock/get_type，飞涨卡第 I/J 列是 get_type/stock。序号 `id` 从 1 自动递增，只用于本批活动标识，不是后台真实活动 ID。

## 必填与默认

- 用户必填 `title`、`city_ids`、`price`、`sale_start_time`、`sale_end_time`、`effect_start_time`、`effect_end_time`，以及至少一组 begin/end 时段。
- 飞涨卡额外用户必填 `reward_percent`、`max_amount_of_order`。
- 两种卡的标签/获取方式/库存/单量/品类/人群默认项由 `defaults.json` 保存；规则按类型分别配置。
- 默认 attention 从对应模板“活动信息”第 3 行取得：免佣 AA3，飞涨 AC3。不得混用、缩写或自行重写完整文案及换行。
- 售价、日期、奖励时段和飞涨权益不能从第三行示例或默认项补造。多城市仍是一条活动，不擅自拆成多条。

## 字段约束

| 字段 | 校验 |
| --- | --- |
| title | 非空字符串，按用户原文保留 |
| city_ids | 非空城市名称或名称数组，英文逗号连接；不查数据库、不把名称转换成 ID |
| tag | 普通卡或早鸟卡 |
| get_type | 非空文本；模板没有声明完整枚举，不限制为“购买”一种 |
| stock | 1–100000 的整数，含两端 |
| price | 0–5000 元，含两端；整数或最多两位小数，输出固定两位小数文本 |
| card_rule | 对应类型的固定字面枚举；“x”不替换成单量数字 |
| order_limit | “每天前x单”或“累计前x单”规则必须为整数；“单单”规则可明确留空，未覆盖时仍沿用默认 99 |
| reward_percent | 飞涨卡的整数值，原模板没有声明上下限；不添加自行猜测的范围 |
| max_amount_of_order | 飞涨卡每单上限 0–100 元，含两端；整数或最多两位小数 |
| join_dri_tag、forbid_dri_tag | 默认空；填屏蔽人群时必须有参与人群。保留用户提供的文本，不猜测多值格式或真实后台 ID |
| sale/effect 日期字段 | 严格 `YYYY-MM-DD HH:MM:SS`，合法日期，各自开始不晚于结束；不限制两种区间相互重叠或日期必须晚于今天 |
| begin_time_n、end_time_n | 严格 `HH:MM:SS`，00:00:00–23:59:59，成对，至少一组；最多现有 5 组，未使用组均留空 |
| order_category | 普通单、特赚单、快车单、增量单、稳收单；英文逗号连接或字符串数组，不添加新枚举 |
| attention | 默认完整模板文案；用户可提供新字符串覆盖，明确空字符串表示清空，null 不代替默认 |

整数与金额不接受布尔值。金额不静默舍入，超过分的精度先修正输入。JSON 小数以精确十进制读取，0 不被当成缺失。文本以 `=` 开头也不作为 Excel 公式。

## 未验证项

1. “重要说明”写时段 1–9，实际表头只有 1–5。当前只支持实际 5 组，需要更多时段时应取得后台对应新模板。
2. 人群过期时间必须晚于活动结束时间，但这两个模板没有提供人群有效期元数据。非空人群在摘要中标记 `population_expiry` 未验证，不凭标签推断。
3. 跨午夜时段的后台解释未定义。按用户输入保留配对文本，标记 `overnight_period_semantics` 未验证，不自行拆分或改变结束日期。
4. 城市/人群真实存在性及后台导入结果不能由本地 XLSX 校验证明。生成后仍需目标后台实际验收；本 Skill 不自动上传或创建卡券。

# lx-kaquan 卡券文件生成

生成用于宏鹄后台“批量创建”的本地 XLSX。只生成文件，不上传、不创建真实卡券。AI 收集用户提供的活动信息，`scripts/generate_cards.py` 确定性校验并生成；详细字段约束见 [field-rules.md](references/field-rules.md)，不要猜测模板未说明的后台规则。

## 目录与运行要求

- `assets/feizhang_template.xlsx`、`assets/mianyong_template.xlsx`：只读原始模板，分别用于飞涨卡、免佣卡。
- `defaults.json`：已确认默认值。两种卡均为普通卡、购买、库存 999、单量 99、品类“普通单,特赚单,稳收单”，参与和屏蔽人群为空；规则分别为“每天前x单飞涨”和“每天前x单免佣”。该文件的 `attention=null` 表示读取对应模板第 3 行的完整现有活动要求，保留换行。
- `references/` 保存字段规则；`scripts/` 保存唯一生成入口；`tests/` 仅使用虚构记录；`agents/openai.yaml` 是平台元数据，脚本不依赖它。
- 使用 Python 3.9+ 和 `openpyxl>=3.1,<4`；依赖声明在 `requirements.txt`。优先用本机现有可用环境，不依赖个人绝对路径、数据库、账号、网络或 MCP。
- 运行环境缺少依赖时明确报告；只读预检不安装依赖。需要准备环境时优先任务虚拟环境，不安装全局包，不修改系统配置。
- 业务输入、输出和临时文件放在任务工作区，不放入 Skill 或 Git。使用用户指定目录或既有输出目录；新目录先定义用途、命名及清理约定。本仓未归类任务按 `workspace/00todo/YYYYMMDD_事项说明/`，源文件保留，清理由用户决定。

## 执行契约

### 输入

用户明确选择 `feizhang`（飞涨卡）或 `mianyong`（免佣卡）；一次一种类型。混合需求分成两批、两个文件。

两种卡都必须由用户提供：

| 英文字段 | 用户必填内容 |
| --- | --- |
| `title` | 对外活动标题 |
| `city_ids` | 城市名称；多城市用英文逗号连接，或提供字符串数组，不能写成城市 ID |
| `price` | 售价，0–5000 元，最多两位小数，允许 0 |
| `sale_start_time`、`sale_end_time` | 售卖开始、结束日期时间 |
| `effect_start_time`、`effect_end_time` | 有效期开始、结束日期时间 |
| `begin_time_1`、`end_time_1` 等 | 至少一组完整奖励时段，可使用现有第 1–5 组 |

飞涨卡另外必须由用户提供：`reward_percent`（整数飞涨百分比）和 `max_amount_of_order`（每单奖励上限，0–100 元，最多两位小数）。不从示例或默认文件填充这些必填值。

脚本输入为 UTF-8（允许 BOM）`.json`，顶层是活动对象数组，字段使用对应模板第 2 行的英文名。AI 可从聊天、表格或文件整理，但必须保持用户数据和活动一一对应；不自动按城市、日期展开，不去重或合并。不传 `id`，由脚本从 1 递增生成。

用户明确提供的值覆盖默认值；未提供字段才用默认。售价 0 是有效值，不能用真假判断套默认。显式 null/空值不会暗中退回示例或默认：必填和非空默认字段报错；参与/屏蔽人群可为空，单单规则的单量可为空，未用时段为空；活动要求可用明确的空字符串覆盖文案，null 不表示使用默认。

奖励时段最多 5 组，完整填写 `begin_time_n`/`end_time_n`，不能添加第 6–9 组。模板说明写 `1~9` 而实际表头只有 5 组，按现有列生成；需要更多时段时先确认新后台模板。

### 输出

- 新建 `.xlsx`，输出父目录须已存在；已有文件、目录或符号链接目标一律停止，不提供覆盖开关。建议使用新的 `feizhang_cards_YYYYMMDD_HHMMSS.xlsx` 或 `mianyong_cards_YYYYMMDD_HHMMSS.xlsx` 文件名。
- 保留原工作表名称和顺序、“活动信息”前两行及“重要说明”全部内容、格式、合并区域、列宽和行高。
- 第 1 行是中文列名，第 2 行是英文字段，真实活动从第 3 行开始。第三行原示例只用作格式和默认活动要求来源，其余示例值不能混入输出。
- 飞涨卡 29 列，免佣卡 27 列；两种模板的库存/获取方式位置不同，按各自表头写入。
- 每个活动字段都写成文本并采用 `@` 格式。日期时间为 `YYYY-MM-DD HH:MM:SS`，时段为 `HH:MM:SS`，金额固定两位小数，不静默舍入。以 `=` 开头的标题或文案也作为原始文本写入，不成为公式。
- 不添加摘要、测试、校验或其他工作表，不加入示例行和额外后台字段。
- CLI 返回活动数量、列数、使用默认项的计数、输出路径、读回状态及尚未验证项；不打印完整活动记录。

### 验收

整批校验通过后才写输出；存在错误时按记录和字段提示，不跳过坏行生成部分文件。

保存后脚本重新打开实际文件，核对工作表顺序、前两行和重要说明的内容/样式/合并区域、全部活动行数，以及每个字段的实际值、类型和文本格式。只有 `status=generated` 且 `readback=passed` 才能交付；读回失败时保留新文件供检查，不报告成功，不自动删除。

交付新文件链接、卡券类型、生成活动数、采用的默认项和本地读回结果，并对照用户原始输入核对活动数量和关键字段。明确“后台导入未执行”；本地文件验收不能证明后台已接受或真实卡券已创建。

城市、人群在后台是否存在未验证；提供非空人群时，人群过期时间未验证。跨午夜时段只保留用户提供的配对时间，摘要提示后台跨午夜含义未验证，不自行拆分或解释为某一天。

## 执行流程与示例

1. 收集类型和全部必填项，只追问缺失或会改变结果的业务信息；其余使用已确认默认值。
2. 整理 JSON，在目标 Python 环境用 `-B` 运行 `--dry-run`。只读模式不创建目录、文件、日志，不连接后台或安装依赖。
3. 用户已要求生成本地文件时，预检通过可直接生成，无需重复询问许可；用户只要求预览时停在 dry-run。
4. 根据读回结果交付；需要后台提交或更改外部状态时另行明确目标和授权。

以下仅为虚构结构示例，不可替代用户缺失的业务输入：

```json
[
  {
    "title": "虚构免佣活动",
    "city_ids": "北京市",
    "price": "10.12",
    "sale_start_time": "2026-10-20 00:00:00",
    "sale_end_time": "2026-10-20 23:59:59",
    "effect_start_time": "2026-10-20 00:00:00",
    "effect_end_time": "2026-10-21 23:59:59",
    "begin_time_1": "07:00:00",
    "end_time_1": "08:30:00"
  }
]
```

预检与生成：

```bash
python -B .workbuddy/skills/lx-kaquan/scripts/generate_cards.py --type mianyong --input "input.json" --output "mianyong_cards.xlsx" --dry-run
python -B .workbuddy/skills/lx-kaquan/scripts/generate_cards.py --type mianyong --input "input.json" --output "mianyong_cards.xlsx"
```

飞涨卡改用 `--type feizhang` 和对应输出名，并补齐两个飞涨必填字段。Windows 可使用 `py -3 -B`，其他平台选择现有 `python`/`python3`。在其他软件或目录中，将入口替换为完整 Skill 所在路径；脚本按自身位置读取模板和默认项，不依赖执行目录。目标软件的 Skill 发现、Windows 和真实后台接受需要在对应环境实际验收。

测试：`python -B -m unittest discover -s .workbuddy/skills/lx-kaquan/tests -p "test_*.py"`。

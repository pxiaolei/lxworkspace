# lx-wenda · 宏鹄产品知识库问答

把「宏鹄 SaaS 产品知识库」（MaxKB）封装成一句话可调用的能力。

已完成项目内迁移和本地执行门禁。CLI、MCP 和 selftest 默认仅预览，服务调用 0 次；真实问答需要本次问题/服务/会话的绑定确认。实际 MaxKB 记录读回尚待授权验收，发布门禁仍为 `R3 / blocked`；离线测试通过不证明实际服务可用。伙伴分发仅含代码和空配置示例。

共享工作区统一从项目根执行 `python tools/run_skill.py wenda "<问题>"`，由入口为当前进程指定根 `config/lx-wenda.json`。独立 CLI 保留现有本地配置兼容；不得继承其他工作区账号。知识库范围可全部分享，凭据线下提供，真实配置不分发。

## 什么时候用

**适用** —— 问「平台怎么用 / 怎么配」这类产品使用问题：

- 「B端开城怎么操作？」
- 「计价配置在哪里配、有什么限制？」
- 「城市规则配置配了不生效，检查什么？」
- 「某某功能的入口和步骤是什么？」

**不适用** —— 问实时业务数据（司机数、订单量、GMV、活动效果）时，用 `lx_shujuku` 查询公司数据库。知识库问答不提供公司数据查询，也不操作 SaaS 后台。

## 现有接口（迁移兼容保留）

入口脚本是本技能目录下的 `ask.js`，用 Node 执行。`ask.js` 只做参数解析，配置读取、`preview_hash`、确认门禁和独立读回校验都在同目录的 `client.js`；MCP 的 `server.js` 复用同一份逻辑。排障查 `client.js`：

```bash
node "<本技能目录>/ask.js" "B端开城怎么操作？"
```

多轮追问时，带上上一轮返回的会话 ID：

```bash
node "<本技能目录>/ask.js" "那关城呢？" --chat <chat_id>
```

参数说明：

| 参数 | 作用 |
|---|---|
| 第一个位置参数 | 问题正文，必填 |
| `--chat <id>` | 复用会话，保留上下文做多轮追问 |
| `--json` | 输出 `{answer, chatId, tokens}` 结构化结果 |
| `--confirmed --expected-preview-hash <HASH>` | 确认本次预览所绑定的问题、服务和会话写入 |

默认仅返回 preview_hash 和服务端动作范围。确认后才会创建会话/消息；复用实际会话时带 `--chat` 并重新预览。独立 GET 记录校验 id、chat_id、problem_text 和 answer_text，失败可能已写入，不自动重试或删除。

## 关键注意事项

1. **单次调用约 20~30 秒**，这是知识库侧的推理耗时，属正常，不要中途放弃或判定失败。
2. **答案在 stdout**，可直接引用；耗时和 token 统计在 stderr。
3. 脚本已丢弃服务端返回的思维链字段（`reasoning_content`，体积约为答案的 10 倍），只保留答案正文 —— 不要绕开脚本直接裸调接口，否则上下文会被撑爆。
4. **会话 ID 不能自己编造**。必须是先用 `GET /chat/api/open` 拿到的、或上一轮返回的。自己拼一个 UUID 会得到 `{"code":500,"message":"对话不存在"}`。
5. 现有本机凭证在 `config.json`，文件已被 Git 忽略；`_user_meta.json` 同样不分享。伙伴只接收代码和 `config.example.json`，另行配置获授权的应用凭据。不要把整个本机目录直接打包。

## 执行契约

### 输入

- 宏鹄 SaaS 产品使用问题；需要追问时使用同一账号上下文中上一轮实际返回的会话 ID。
- Node.js ≥18；不需要 npm 依赖。真实配置仅从本机 `config.json` 或现有 `MAXKB_*` 环境变量读取，不写入命令、日志或 Git。
- 执行前预览，再明确确认服务/问题/会话并传本次 hash；真实协议与读回验收需另行授权。

### 输出

- 现有 CLI 保留答案正文；`--json` 保留 `{answer, chatId, tokens}`，不透传 `reasoning_content`。问答可能在服务端保存会话和消耗模型额度。
- 无答案、超时、认证或服务异常应分别说明；不把生成答案当成确定事实，不承诺当前接口提供独立的文档引用来源。
- 未确认输出预览；已确认且读回一致才输出答案。真实验收前保持发布 blocked。

### 验收

- 本阶段检查目录迁移、配置忽略、命名、Node 语法、CLI 帮助、使用无凭据配置的 MCP 初始化/工具枚举及 Skill 契约。
- `ask.js`、`server.js` 的问答工具和 `selftest.js` 的真实调用动作均为 `R3 / blocked`；普通 inventory 检查通过不等于可发布，`--final` 必须拒绝。
- 离线使用 `node --test test_safety.js`，验证未确认/问题或会话改变 HTTP 0 次，以及独立 GET 不一致拒绝成功；selftest 默认只检查 MCP 预览。不得把实际问答当离线测试，不修改全局 MCP 配置。

## 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `缺少 token` | config.json 没配 token | 填 `token` 字段，或设环境变量 `MAXKB_TOKEN` |
| `对话不存在` | chat_id 是编造的 | 不传 `--chat`，让脚本自己开新会话 |
| `请求超时` | 知识库侧响应慢，超过脚本 `timeout_ms` | 调大 config.json 里的 `timeout_ms`（默认 120000） |
| `问答 HTTP 504` | 网关等待超时，可能已经写入消息 | 先检查服务端记录，再决定是否重新预览/确认；不自动重试 |
| 错误信息冒号后带服务端原文 | 服务端把上游异常写进了响应体，脚本已带出该段文字 | 先按这段原文定性（如 `AccessDenied.Unpurchased` 是模型未授权，需后台处理），不要只看 HTTP 码 |
| `问答返回异常文本，已拒绝当作答案` | 上游异常被服务端存成了消息正文，脚本拒绝把它当答案返回 | 该条记录已可能写入，人工核对后重新提问；不自动重试 |
| `响应不是合法 JSON` | 服务端返回了 HTML 错误页（502/504 等） | 看报错里的 HTTP 码，按上面的条目处理；一般稍后重试恢复 |
| 返回空内容 | 知识库没检索到相关内容 | 换个说法再问，或确认该问题是否在知识库覆盖范围内 |

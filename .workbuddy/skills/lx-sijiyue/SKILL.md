# 司机账户余额查询

## 使用流程

本能力使用宏鹄 SaaS 账号权限，独立于公司数据库账号。只使用用户明确指定的本人账号和 `company_id`，不读取其他工作区或自动选择缓存里的其他账号。租户由使用者在宏鹄工作台核对；名字相近的品牌可能对应不同租户，不猜测、不依赖未分发的租户映射 Skill。

运行环境由 `lx-init` 安装到现有项目虚拟环境；不复制源仓 `.venv` 或另建环境。本能力依赖 pandas、openpyxl、xlrd；代码依赖随包的 `lx-shenfenzheng/scripts/honghu_common.py`，三项必须一起分发。

1. 首次或会话过期时，预览本机登录：

```bash
python tools/run_skill.py sijiyue-login --username <本人账号> --company_id <已核对租户ID>
```

审阅后，以原参数追加 `--confirmed --expected-preview-hash <本次hash>` 打开本机窗口。用户在窗口输入密码并点击「登录并保存」才发送请求并保存缓存；取消不请求、不写入。不得在聊天、命令参数或文件中提交密码。登录可能使同账号旧会话失效。窗口打不开时停止并联系对接人，不改用命令行密码。

2. 预览查询范围（无请求、无缓存读取、无输出目录/报告/日志）：

```bash
python tools/run_skill.py sijiyue --username <本人账号> --company_id <已核对租户ID> --input <司机表.xlsx> --output <新的结果.xlsx>
```

3. 展示输入/输出、字段、行数、待查询司机数、租户、线程数和确认hash；获得该范围查询授权后，原参数追加 `--confirmed --expected-preview-hash <本次hash>`。默认10线程，允许1至10线程。绑定输入文件hash、账号、租户、字段及输出；变化后重新预览。
4. 程序先查询1个待处理司机，验证通过后复用该结果并启动剩余批量。单点失败即停；全部已有值时仅另存并核对，不请求。
5. 写入全新 xlsx 后独立逐单元格读回，汇报填充率、异常分类、输出绝对路径、行数与SHA256。部分失败返回非零，不能称全量成功。

## 数据与异常口径

- 每司机 1 次 `driverAccount/balance`；使用 form 载荷 `driver_id`、`company_id`，不是 JSON。无需 clarify。
- `real_balance`→账户余额，`withdraw_balance`→可提现余额，`is_sign` 的 true/false→是/否；缺失或 null 留空，不转成零或否。
- 可提现余额空字符串表示平台未存，不能报告查询失败或擅自补 0。
- 单点必须返回非空 data；失败时不启动批量。

- 输入支持 xls、xlsx，以及后缀为 xls 但内容为 xlsx 的文件；ID按字符串读取，保留前导零。司机ID列有歧义时必须用 `--id_col` 指定，科学计数法/小数ID不能作为有效司机ID。
- `errno=0` 不等于有数据；缺少 errno、空 basic/data、平台未存和请求失败分别处理。
- `13005` 为会话失效，`13006` 为权限不足，`13008` 为账号或商户禁用：停止后续请求，不自动重试或切换账号。已在途请求可能返回；不把这类失败报告成查无记录，不输出成功文件。
- 输出只补缺失值，保留原表；输出已存在、符号链接或与输入相同均拒绝。新输出的父目录须已存在。
- 密码、ticket、身份证号、车牌、车主、余额和司机异常明细不进入聊天/日志；仅汇报汇总，敏感结果只在用户指定的新文件中保存。
- 缓存仅在本 Skill 的 `scripts/ticket_cache.json`，只保存本机认证信息、账号和租户绑定。旧缓存没有租户绑定时重新登录；不得删缓存来完成共享，不分发已有缓存、临时登录文件或业务表。
- 三项的HTTPS登录与真实服务、Windows窗口/WorkBuddy尚未验收；离线测试通过不等于已联通。不得降级HTTP、忽略证书或临时改签名排错。

## 执行契约

### 输入

- 含司机ID列的 xls/xlsx、本人宏鹄账号、已核对且具有权限的 company_id。
- 输出新路径；登录及真实查询须有当前范围授权和对应阶段的确认hash。
- 不要求提供公司库、私人RDS或维护者凭据。

### 输出

- 新 xlsx，默认 `<输入名>_余额.xlsx`，补齐账户余额、可提现余额、免密状态。
- 仅输出汇总统计、逐单元格读回结论、输出路径及SHA256；无后台数据写入。

### 验收

- 默认预览及过期/错误hash零请求、零缓存读写、零输出写入；账号/租户不匹配拒绝执行。
- 单点失败不启动批量，errno与空值分类准确；解密阶段同样处理会话失效。
- 不覆盖输入或已有结果，输出读回失败不能报告成功；不泄露凭据和敏感结果。
- 离线回归：`python -B -m unittest discover -s .workbuddy/skills/lx-shenfenzheng/tests`，覆盖三个业务入口。真实平台/Windows验收单独报告。

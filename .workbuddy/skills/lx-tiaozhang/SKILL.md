# lx-tiaozhang 调账 CSV 生成

将用户提供的司机数据生成本地调账 CSV。AI 收集和整理数据，使用 `scripts/generate_adjustment.py` 完成校验、输出和读回；最终文件遵守 `assets/` 内两份模板及以下规则。

## 目录与运行要求

- `assets/credit_template.csv`、`assets/debit_template.csv`：分别为补款、扣款原模板，保留第二行说明；只读使用。
- `scripts/`：确定性生成入口；`tests/`：虚构数据的标准库测试；`agents/openai.yaml`：平台显示和发现元数据，生成脚本不依赖它。
- 需要 Python 3.9+，只使用标准库；选择本机可用的 `python`、`python3` 或 Windows `py -3`，不自动安装依赖。
- 模板通过脚本自身位置定位，移动完整 Skill 目录后仍可运行，不要求特定工作目录、MCP、账号或私人配置。
- 用户数据、中间输入和生成文件放在任务工作区，不能放入 Skill 目录或 Git。输出目录使用用户指定位置或任务已有输出目录；新目录先约定用途和命名，源文件保留，由用户决定何时清理。本仓未归类任务遵循 `workspace/00todo/YYYYMMDD_事项说明/`。

## 执行契约

### 输入

用户必须明确补款或扣款，并为每条记录提供司机 ID、姓名、金额。可以来自聊天文字、粘贴表格或文件，保持记录与原始用户数据一一对应；不猜测缺失值、不自动合并或去重。

| 字段 | 要求 |
| --- | --- |
| `driver_id` | 必填字符串，保留长 ID 和前导零；不能用姓名反推 ID。 |
| `driver_name` | 必填非空字符串，使用用户提供的姓名。 |
| `amount_yuan` | 必填，单位元，`0.01–5000.00`，最多两位小数；补款和扣款均填正数。 |
| `order_list` | 选填，空值留空；多个订单以英文逗号连接，也可在 JSON 中提供字符串数组。 |
| `activity_id` | 选填字符串，空值留空。 |
| `desc` | 用户提供时使用原文，最多 50 字（按字符计，标点/空格计入）；未提供、null 或空白时，按类型填“补款”或“扣款”。 |

脚本支持两种输入，文件后缀必须是 `.json` 或 `.csv`：

- JSON：顶层为记录对象数组，字段使用上表英文名，ID 必须为字符串；金额推荐字符串，也支持 JSON 数值。必填缺失、未知字段、非法类型、超过两位小数均报错。
- CSV：UTF-8（允许 BOM），表头可省略选填列，但必须包含三个必填列；只接受上表字段，不猜测中文表头。若第二个逻辑记录与所选原模板的说明行完全相同，才跳过该说明记录；不会按行号删除真实司机数据。

中文表头或自然语言由 AI 先整理为明确的英文 JSON 契约。若金额单位、类型或字段对应不明确，先补充信息；数据缺失或不合规时报告具体记录和字段，修正整批后再生成，不悄悄跳过错误行。

### 输出

每次生成一种调账类型：`credit` 对应补款，`debit` 对应扣款。混合需求拆成两批、分别生成。

- 新建 `.csv`，父目录须已存在；目标已存在或是符号链接时停止，改用新文件名，不覆盖源数据和旧结果。
- 建议文件名：`credit_adjustment_YYYYMMDD_HHMMSS.csv` 或 `debit_adjustment_YYYYMMDD_HHMMSS.csv`；重跑使用新的文件名。
- UTF-8 BOM 编码、CRLF 换行，字段顺序固定为 `driver_id,driver_name,amount_yuan,order_list,activity_id,desc`。
- 第一行保留表头，第二行直接开始用户数据，不包含模板说明行、示例记录、汇总行或额外列。
- 金额按两位小数文本写入，如 `25.00`、`0.10`、`5000.00`；精度不合规时拒绝，不擅自舍入。
- CSV 写入器处理逗号、引号和换行，不用字符串拼接整行；不向金额添加货币符号、单引号、制表符或 `="25.00"` 公式。
- CLI 只输出摘要或行号/字段错误，不打印完整司机记录。摘要包含类型、记录数、金额合计、默认说明数量、绝对输出路径和读回状态。

CSV 不保存 Excel 的单元格类型，能够保留 `25.00` 这样的完整金额字符。验收以文件原文和 CSV 读回为准；Excel 再次打开时的显示可能自动变化。查看或编辑时按文本导入 ID 和金额列，重新保存后再次核对原文。

### 验收

整批预检通过后才允许生成。脚本保存后读取实际文件，核对 BOM、全部字段和记录、CRLF、金额文本及原始写入字节；读回失败不报告成功。

交付文件链接、补款/扣款类型、记录数、金额合计、默认说明数量和本地读回结果。脚本仅校验文件契约，无法证明司机 ID 真实存在、姓名匹配或后台已接受，更不代表已经执行调账。

## 使用步骤与命令

1. 从用户请求确定类型及输出目录，整理输入；只追问缺失的必填信息。
2. 对全部记录运行 `--dry-run`，确认数量、合计和默认说明数量符合用户请求。该模式不创建目录、输出或日志；将 Python 入口设为 `-B` 避免字节码缓存。
3. 用户已要求生成本地文件时，预检通过可直接运行生成命令，无需重复询问许可；若用户只要求预览，则停在 dry-run。
4. 只在 `status=generated` 且 `readback=passed` 时交付，并对照用户原始数据复核记录数和金额合计。

以下 JSON 仅为虚构用法示例，实际运行只能使用用户提供的业务数据：

```json
[
  {
    "driver_id": "00123456789012345678",
    "driver_name": "示例司机",
    "amount_yuan": "25",
    "order_list": ["000001", "000002"]
  }
]
```

在本仓执行预检：

```bash
python -B .workbuddy/skills/lx-tiaozhang/scripts/generate_adjustment.py --type credit --input "input.json" --output "credit_adjustment.csv" --dry-run
```

生成文件：

```bash
python -B .workbuddy/skills/lx-tiaozhang/scripts/generate_adjustment.py --type credit --input "input.json" --output "credit_adjustment.csv"
```

扣款将 `--type` 改为 `debit`，输出名使用 `debit_adjustment.csv`。其他软件通过完整 Skill 目录导入/发现；将命令中的入口换成该 Skill 所在路径即可，不改变业务逻辑。Windows 可把 `python -B` 换成 `py -3 -B`。不同平台的技能发现、Windows 和后台接受仍须在目标环境实际验收。
